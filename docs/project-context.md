# Project context

## Goal and scope

Build a browser-based, guitar-only rock rhythm game as a React learning project, inspired by Clone Hero / Guitar Hero. Use five descending lanes and disc-shaped notes on a perspective highway.

First-phase target: per-song difficulties, synchronized audio, chords, sustains, streaks, score multipliers, boost, pause/restart, results, rock menus, audio/SFX settings, remappable keys, and optional per-song video. The user selected direct D/F/J/K/L keyboard play (green/red/yellow/blue/orange) without a separate strum key, with default scroll speed 2×. Saved custom settings remain in effect; Reset restores these defaults. Future direction includes public release, SEO, GA4/Clarity, and synchronized versus rooms for up to four players; these integrations are not implemented. Additional instruments, accounts, and public uploads are not established requirements.

## Technical foundation

- React, TypeScript, Next.js 16.3.5 App Router, ESLint; pnpm with `pnpm-lock.yaml`. Vite tooling has been removed.
- `src/app/`: prerendered routes `/`, `/catalog`, and `/play`, shared global CSS, Spanish HTML, and metadata. Gameplay requires an explicit validated catalog attempt held in client session memory; song/difficulty never appear in its URL. Direct access or full reload returns to the catalog. Canvas/Web Audio initialize only after mounting in the browser.
- `src/App.tsx`: shared client session/settings provider, restoring localStorage after hydration without overwriting saved settings. `MenuRoutes.tsx` connects existing screens to Next navigation. `HomeScreen`, `SongCatalog`, `PreviewPlayer`, and `GameScreen` separate welcome, library browsing, audio samples, and engine lifecycle.
- `src/components/SettingsPanel.tsx` and `src/game/settings.ts`: shared song-themed translucent settings dialog, explicit key-capture state and duplicate-key feedback, five unique key bindings, 0.5–4× visual scroll speed, and localStorage persistence. Shared `VolumeControl` exposes immediate 0–200% volume and mute in the right side of Home, catalog, and play headers; volume is removed from Settings, and Save/Reset preserve the current master volume. Menu audio uses a Web Audio gain node above 100%; gameplay already uses master gain. Key/speed changes apply on Save; Reset edits their draft. Escape cancels active key capture before closing the dialog.
- `src/game/mechanics.ts`: sustain scoring/releases, boost phrases/energy, and health rules.
- `src/songs/`: runtime types, generated-manifest catalog, and selected-song audio loading. `src/generated/songs/` holds reproducible derived charts/manifest; `src/musics/` holds unchanged original packages.
- `src/songs/presentation.json`: optional manually curated palettes, backgrounds, descriptions, and display metadata keyed by imported ID; import never overwrites it. The catalog layers these over generated metadata, with artwork/neutral palette fallbacks. See [song presentation](song-presentation.md). Initial palettes are editorial starting points; gameplay lane colors remain fixed.
- `src/game/prototype.ts`: input, judgment, score, and playback orchestration.
- `src/game/renderer.ts`: Canvas 2D perspective highway/discs/tails/effects.
- `src/game/demo-audio.ts` and `chart.ts`: isolated synthetic test fixture.
- `scripts/import-songs.mjs` / `song-package.mjs`: generic folder discovery/import and error reporting. `midi-chart.mjs` / `text-chart.mjs`: MIDI and `.chart` five-fret lead-guitar adapters.
- `scripts/prepare-song-assets.mjs`: validates inputs and copies only referenced charts/media into an exclusively generated `public/songs` cache, prepared on import/dev/build. Original `src/musics` packages and derived `src/generated/songs` remain canonical inputs; do not put originals in the ignored public cache. See [Next.js migration](next-migration.md).
- PixiJS remains a proposed future renderer, not installed. MIDI parsing uses `midi-file` during import only; no MIDI parser runs in the browser.
- See [song integration](song-integration.md), [game plan](game-plan.md), and [chart research](chart-research.md).
- Selected compatibility direction: preserve community packages as canonical input; read extracted folders through generic MIDI/`.chart` adapters without per-song code. ZIP/SNG readers and local upload UI remain pending. Generated JSON is a reproducible derived cache, not a user-authored format. See [song architecture](song-architecture.md).

## Current state

- Finished gameplay emits one immutable result before ending gameplay, with actual score, highest group streak, completed groups, missed groups, wrong presses, early sustain releases (including resume), accuracy, unresolved groups for early failure, completion flag, and ISO completion time. Chords count as one group; accuracy is completed groups / all playable groups, with open notes still excluded. Errors sum missed groups + wrong presses + sustain breaks; detailed counts remain in stored results but are omitted from the compact summary. Grades: completed error-free 100% = SS; >=98% S; >=90% A; >=80% B; >=65% C; otherwise F. Failed or empty attempts are F. Timing-quality judgments are not implemented.
- `ResultsScreen` replaces the plain end overlay with song-themed rounded, compact statistics tabs connected to a prominent circular grade disc, without an enclosing rectangular card. The compact layout centers the grade disc alongside track/statistics as a whole, with replay/catalog actions centered below. A 1.5-second reveal counts score/accuracy/maximum combo upward and fills the accuracy ring before revealing the grade; reduced-motion shows final values immediately. Animated counters expose stable final values to assistive technology, and animation frames are canceled on unmount. Artwork, score, accuracy, maximum combo, hit/error totals, prominent local date/time beside the track, replay/catalog buttons, and arrow/Enter/Escape navigation remain available. `riff-results` stores up to 50 finished attempts in localStorage with song ID/difficulty; this is device-local history without a history browser or account sync. Storage failure is shown without blocking results. Restart resets attempt statistics; canceled loads/manual exits do not create results. Results were browser-checked after an actual failed song at 1280×720 and 390×844; grading, completed chord counts, one-time finalization, restart reset, and bounded/storage-failure history are tested.

- Results retain song audio at 15% of the configured master volume. Early failure smoothly lowers the existing sources; completion fades in a synchronized loop of the final 20 seconds shared by all stems, reusing decoded buffers. Restart, manual stop, and exit stop result sources; result playback cannot accept gameplay input. Volume changes retain the quiet factor, including zero volume. Audio continuity, loop setup, restart/exit cleanup, and input isolation have regression coverage.

- Route loading uses `src/app/loading.tsx` with a shared song-themed loader. Play chart loading and engine audio preparation reuse that visual: blurred song backdrop, a minimal horizontal artwork/track/difficulty/charter composition without a card background, and real download/decode stages. Audio/image preparation keeps the loader visible for at least three seconds (overlapping real loading, not added after slow downloads), then fades it out over 400 ms. After this, the loader is replaced by a 3-second 3–2–1 overlay on the visible highway before synchronized source scheduling; decorative highway lines scroll while the board and score/life indicators appear progressively; no notes, audio clock, or judgment advance during this pre-game phase. Reduced-motion uses static visuals. Escape cancels both loading and the pre-game countdown. Image failure does not block play; countdown waits while the page is hidden. Map failures expose Retry/Back; audio failures retain the replay/back controls. Escape can cancel loading back to catalog. Pending map/audio fetches and countdown timers are canceled on exit/restart; in-flight browser audio/image decoding cannot be interrupted, and canceled results are not started. No synthetic progress percentage is shown; the minimum preparation duration is cancellable on exit and applies to restarts too. Loader was checked at 1280×720 and 390×844, including countdown completion and Escape pause.
- Menus prefetch adjacent Next routes. Catalog warms only the selected chart after 400 ms of stable selection; chart cache holds one successful song and failed/aborted requests are not cached. Complete audio is loaded sequentially only on Play and retained for restart within the engine, then released with the engine on exit; no full-library decoded-audio cache is used.
- Sorted chart/beat time bounds restrict rendering and hit lookup to visible/judgment windows while keeping original indices. Expiration advances a cursor and resets on restart. Boost membership/ranges and static background gradients are cached rather than rebuilt every frame; reduced-motion media queries are reused, and React status text updates are limited to 5 Hz during play while pause/end changes remain immediate. Regression coverage includes chords, sustains, boost, restart/pause, duplicate timestamps, logarithmic bounds on 30,000 notes, and preparation cancellation. These changes reduce unnecessary work; hardware-specific frame-time profiling remains pending, so stutter elimination is not established.
